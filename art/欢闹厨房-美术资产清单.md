## 1. 命名与规格口径

### 1.1 四段式命名

```
<类别前缀>_<对象>_<变体或状态>_v<版本>.<扩展名>
例：char_maixiaoman_normal_v1.png
    ui_recipe_page_locked_v1.png
    fx_frosting_reveal_v1.png
    anim_hero_knead_06_v1.png
```

| 段 | 取值 |
|---|---|
| 类别前缀 | `char` / `env` / `ui` / `icon` / `fx` / `anim` / `img` / `font` |
| 对象 | 小写英文 + 下划线，不用中文与空格 |
| 变体 | `normal` / `focus` / `fail` / `happy` / `pressed` / `disabled` / `locked` / `night` / 尺寸档 |
| 版本 | `_v1` 起步，迭代 +1；旧版改名 `_deprecated` 保留，**不删** |

**双版本后缀**：`_src` = 生成原图（纯 `#FF00FF` 底，可复核）；无后缀 = keyout 后的透明底成品。脚本允许 `_src` / `_deprecated` 两种后缀。

### 1.2 规格字段（每项必填，下表已全填）

资产名 / 类别 / 画布尺寸 / 格式 / 透明底 / 朝向 / 图集分组 / 优先级 / 状态 / 阻塞什么。

### 1.3 图集分组

| 分组 | 同屏内容 | 说明 |
|---|---|---|
| `atlas_char` | 七位角色 + 状态 | 同屏同族，统一描边与识别色 |
| `atlas_kitchen` | S1 后厨 + 制作 HUD + 原料图标 | P1 练习关 / P3 挑战关同时出现 |
| `atlas_hall` | S2 大堂 + 柜台 + 结算面板 | P4 / P6 / P8 同时出现 |
| `atlas_recipe` | S4 菜谱界面 + 页三态 + 糖霜特效 | G3 显形仪式专用 |
| `atlas_ui_common` | 通用按钮 / 面板 / 弹窗 / 气泡 | 全局复用 |
| `atlas_icon` | 功能图标（单色可染） | 统一 96×96 |
| `atlas_fx` | 反馈特效贴图 | 位移 / 缩放 / 透明度由代码做 |
| `standalone` | 全屏场景底图 / 终章插画 | 不进图集，可延展，不强制 2 的幂 |

**朝向**：全项目角色、道具**只做朝右单方向**，左向由代码水平镜像。
例外（必须左右各出一版）：沈如意摊位的算盘（不对称持握）、雷千层的小秤（单手持）、顾苦《作战记录簿》的印章（含文字标识倾向）——镜像会变成反手，已在 B3 / B4 单列。

| **B5** | 序列帧 + 反馈特效 | 依赖前四批定稿，最后做 | 5 | B1–B4 全部冻结 |

> **B6 排最后**：七人同框要等七位角色（B2）全部定稿，否则是七张不同批次的图硬拼。

## 6. 产出与放量纪律

1. **B1 定稿前不启动 B2**。第 1 批只出 2 张，通过六维评审（剪影 / 明度 / 构图 / 一致性 / 技术合规 / 可用性）后才放量。
   > **跳批记录（2026-11-14 · 按用户指令）**：本轮先出 B3-A 的 4 个常驻场景，未等 B2 角色定稿。理由：常驻场景只用冻结的 `STYLE BLOCK v1`，不依赖角色立绘，且玩法流程 3.1 的场景验收前置。代价：**跨类别一致性（角色 + 场景拼同屏）尚未验证**，B2 定稿后须补做一次比对；该比对未通过前不启动 B4。
2. 每张生成后：纯色底 `_src` → `keyout` 转透明底 → `trim` 裁边 → `check` 校验 → `sheet` 缩略图测试。
3. 双版本都在、命名带 `_vN`、标注 AI 生成来源与关键参数，才算交付。
4. **先调好一张再推进下一张**；同一提示词重试不超过 3 次，超过走三级降级。
5. 程序化叠加优先：稀有度边框、血条/进度、状态色、换色皮肤一律交给代码，不生成 N 张。
6. 每批结束做三道一致性比对（同族 / 同对象状态 / 跨类别）；比对未通过前不进入下一批。
