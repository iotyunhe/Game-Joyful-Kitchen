
> **为什么必须定义场景变体（对提示词包 §5.1 例外说明的勘误）**
> 原 §5.1 写「只允许把品红底那一句替换成 full-bleed 句，其余 TECHNICAL 保持不变」。实际复核发现**另外两句同样与满幅场景冲突**：`Subject fully inside the frame, centered, with a 10% safe margin...`（要求主体居中留白）与 `One single subject only, isolated.`（要求单一抠图主体）。三条同时下发给模型会互相矛盾。
> 故本批次定义 `SCENE TECHNICAL v1`，共替换三句：背景句、安全边距句、单主体句；并补入两条满幅构图约束（上部 HUD 留白、右下角纯色区）。**STYLE BLOCK v1 一字未动**；角色 / 道具 / UI 批次仍使用原 `TECHNICAL v1`，两套并存、互不覆盖。
> 右下角纯色区是为**平台水印清除**预留的工程约束：满幅图不能像抠图资产那样直接把右下角置透明，必须有一块可无损回填的平坦色块。

## 5. 规格与处理链路

| 项 | 值 |
|---|---|
| 生成参数 | `quality medium` / `background opaque` / `revise false` / 竖屏尺寸 |
| 原图 | `source/<资产名>_v1_src.png`，不透明，保留供复核 |
| 成品 | `final/<资产名>_v1.jpg`，1080×1920 不透明，`standalone`；`source/` 的 PNG 原图即无损精修母版 |
| 规格化 | 等比裁切到 9:16 后等比缩放到 1080×1920；**禁止拉伸变形** |

| AI 标注 | 来源 AI 图像生成，风格 STYLE BLOCK v1 + SCENE TECHNICAL v1，需人工精修与合规确认后方可作最终素材 |

### 6.5 同族一致性结论

接触表（4 张 / 单格 220px）通过：缩略图尺寸下仍可分别辨认厨房、大堂、街面、菜谱书页；四张描边色、哑光平涂、奶油暖色一致，无明度或饱和度突变，无纯黑描边、无锐角、无写实照片感。S4 为**正面视角的元场景**，与三张 45° 俯视物理场景的视角差异是设计意图，不计为漂移。
