## 2. 四段结构与变量槽位

```
[STYLE BLOCK v1]   ← 冻结，逐字复制
[SUBJECT]          ← 每次换：本张画什么
[CANVAS]           ← 按资产换：尺寸、朝向、留白
[TECHNICAL v1]     ← 冻结，逐字复制
```

| 槽位 | 取值范围 | 更换频率 | 备注 |
|---|---|---|---|
| `{角色}` | 麦小满 / 糖老书 / 雷千层 / 顾苦 / 沈如意 / 周伯 / 豆豆 | 每张换 | 只换识别色与服饰，头身比与描边不动 |
| `{识别色}` | 七色见风格提案 2.1 | 每角色换 | 一次只变一个槽位 |
| `{状态}` | `normal` / `focus` / `fail` / `happy` | 每状态换 | 光照方向必须与常态一致 |
| `{场景}` | S1–S9 | 每张换 | 45° 俯视固定 |
| `{点心}` | 焦糖布丁 / 千层酥 / 桂花糕 / 海盐焦糖 | 每张换 | 糖霜白只给显形态 |
| `{尺寸}` | 1024×1024 / 1080×1920 | 按类别固定 | 角色 1:1，场景 9:16 |
| `{朝向}` | 朝右 | **全项目固定** | 左向由代码镜像 |

**一次只变一个槽位**。同时改识别色、尺寸与朝向，出问题时无法归因。

## 9. 双版本与后处理命令（按 B1 实跑结果修订）

> **先读第 13 节实跑记录**：原计划「统一按 `#FF00FF` 用 `keyout` 抠图」在实跑中被推翻——两张图的底色根本不是 `#FF00FF`，且全局颜色匹配会误抠头发与围裙。下面是**修订后可用**的链路。

```bash
# 0) 生成：输出目录 art/generated/batch01/source/
#    参数：size 1024x1024 / quality medium / background opaque / revise false
#    文件重命名为 <资产名>_v1_src.png

# 1) 逐张取色（必做，不能假设底色是 #FF00FF）
python art_asset_tools.py palette source/char_maixiaoman_normal_v1_src.png --top 8
python art_asset_tools.py palette source/img_dessert_pudding_v1_src.png --top 8

# 2) 边缘连通抠图（不要用全局颜色匹配的 keyout，会误抠主体内部相似色）
#    从四边出发，只把「与边缘连通 + 与底色差 < 35」的像素置透明；
#    主体内部被描边隔开的相似色不连通，得以保留。
#    同一步清除右下角平台水印区域、裁到 bbox、等比缩放居中到 512×512 透明画布。
#    实际脚本见第 13.5 节，输出到 final/<资产名>_v1.png

# 3) 规格与命名校验（只跑 final/，src 原图另存 source/ 不参与）
python art_asset_tools.py check final/

# 4) 接触表：10% 缩略图测试 + 三道一致性比对
python art_asset_tools.py sheet final/ --cols 2 --cell 160
```

**护栏**（脚本内建，别绕过）：`--out` 不能与输入同路径，否则会静默覆盖原图；`--tol` 不接受负数；整图被判为底色时报错退出码 3，此时先用 `palette` 取真实底色再重试。

**目录约定**：`source/` 存不透明纯色底原图（可复核）、`final/` 存 512² 透明底成品、`_contact_sheet.png` 存缩略图测试结果。`check` 对 `_src.png` 会报「PNG 无透明通道」——这是脚本口径与「纯色底版本应不透明」的定义冲突，故把 src 移出被校验目录，不修改 src 本身。
