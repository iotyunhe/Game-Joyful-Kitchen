> 版本 v1.0 ｜ 日期 2026-11-14 ｜ 设计分辨率 1080×1920（竖屏）｜ 目标平台：手机为主、PC 兼容（承 GAMEPLAY.md 假设 A1）｜ 引擎：未定，规格与引擎无关

## 0. 结论先行

风格定名 **「糖霜团子 / Sugar Dumpling」**：软描边 + 圆润剪影 + 奶油暖色 + 哑光粉质的 2D 手绘可爱风。
定调的三条硬理由，全部来自项目设定而非审美偏好：

1. **谐星反派的出糗桥段不能显得可怕** → 必须零锐角、零黑线、零硬阴影；顾苦踩糖粉滑倒、雷千层数 1024 层到天黑，靠圆润剪影才能落成笑点而不是事故。
2. **「显形 ≠ 学会」是核心反馈** → 糖霜白 `#FFF7EA` 被留作**唯一最高明度**，专供第 100 页齐鸣与单页显形；它不能被日常 UI 用掉，否则仪式感失效。
3. **大团圆终章七人同框** → 七位角色共用同一套描边、阴影与高光（辅色体系），**只换识别色**，同屏才不会像七张不同游戏的图拼在一起。

## 2. 色彩板（6 色 · 已冻结）

| 角色 | 色名 | 色号 | 明度 L | 主要用途 | 占比上限 |
|---|---|---|---|---|---|
| **主色** | 焦糖橘 | `#E8A05C` | 68 | 主角围裙、主按钮、店招牌、暖光、烤制进度 | 25% |
| **辅色** | 蜜桃粉 | `#F3BFC0` | 79 | 腮红、甜点主体、次要控件、女性角色识别底 | 20% |
| **强调色** | 糖霜白 | `#FFF7EA` | 97 | **专供显形仪式 / 糖霜 / 最高亮面 / 选中态** | 15% |
| **交互色** | 莓果红 | `#D9534F` | 53 | 倒计时、失败提示、干扰事件警示；不用于装饰 | 5% |
| **背景色** | 奶油杏 | `#F5E4C9` | 89 | 场景大底、面板底、列表底 | 30% |
| **阴影/描边色** | 焙茶棕 | `#5A3B2E` | 24 | 统一描边、最深暗部、正文文字 | 5% |

**硬规则（写进规格，不许凭感觉调）**

1. 同屏高饱和色不超过 3 种；莓果红是唯一高饱和交互色，超了就压掉装饰色。
2. **糖霜白不得被日常 UI 占用**。按钮常态底用焦糖橘或奶油杏，只有「页显形 / 选中 / 百页齐鸣」才允许出现 L≥95 的大面积白。这是 G3 关门落点仪式感的预算来源。
3. 同族对象（七位角色、同一批甜点）**共用描边色、阴影色、高光色**，只换识别色区分个体。
4. 状态不能只靠颜色：倒计时 = 莓果红 + 沙漏形；禁用 = 去饱和 + 斜杠图标；增益 = 焦糖橘 + 上箭头。
5. 色值统一按 sRGB 十六进制定义一次；本作 2D，无需线性空间换算。

### 2.1 角色识别色（色彩板派生，不占 6 主位）

> 全部从 6 色板**降饱和 / 调色相**派生，共用 `#5A3B2E` 描边与 `#FFF7EA` 高光。这是「七人同框不成拼盘」的执行方式。

| 角色 | 识别色 | 色号 | 设定依据 |
|---|---|---|---|
| 麦小满（主角） | 焦糖橘 | `#E8A05C` | 主色，视觉重心永远在他身上 |
| 糖老书 | 旧纸黄 | `#E5CF9E` | 泛黄书页 + 糖丝眼镜 |
| 雷千层 | 瓷青蓝 | `#84A6BB` | 冷面、只信秤；低饱和冷色，但**不是反派黑** |
| 顾苦 | 苦瓜绿 | `#89A578` | 窗帘改的黑斗篷 → 减重为墨绿斗篷（下摆流苏保留） |
| 沈如意 | 藕荷紫 | `#C3A2BE` | 温柔利落；戴墨镜摆摊时识别色不变，靠剪影认得出 |
| 周伯 | 灰茶褐 | `#A08D78` | 沉默的老邮差，低存在感但灰度下仍可分 |
| 豆豆 | 奶黄 | `#F2CE72` | 童言担当，全队最高明度识别色（主色同族） |

> **顾苦斗篷的减重说明**：设定写「黑斗篷」，但纯黑违反「不用纯黑 / 不阴森」的锚点。改为**墨绿 `#3E5545`（焙茶棕向冷偏移）+ 蜜桃粉流苏**，保留「自己缝的窗帘」这一喜剧来源，剪影仍是斗篷。**这是风格对设定的唯一一处反向修正，已显式记录，不暗改。**

## 3. 明度阶梯与背景 / 主体分离要求

| 层级 | L 区间 | 本作对应色 | 用途 |
|---|---|---|---|
| 高光 | 90–100 | `#FFF7EA` L97 | 糖霜、显形、选中态（独占） |
| 主体亮面 | 60–80 | `#F3BFC0` L79 / `#E8A05C` L68 | 受光面、甜点顶部 |
| 主体中间调 | 40–60 | 派生识别色压暗一档 | 固有色、衣料、木器 |
| 主体暗部 | 20–40 | 同色系低明度 | 背光面，禁止纯黑 |
| 背景（日间） | 84–92 | `#F5E4C9` L89 | 场景大底、面板底 |
| 背景（夜/评定场） | 18–32 | `#3E3550` L24 | S5 评定场、S7 云端大会、回忆画面 |
| 描边 / 统一轮廓 | 5–20（本作 24） | `#5A3B2E` L24 | 全资产强制统一 |

**分离双重保证（解决「可爱风浅背景容易糊」这个具体问题）**

- **日间浅背景**：背景压在 L 84–92，主体中间调落在 L 40–60，且**所有主体强制 `#5A3B2E` 描边**。转灰度后主体形成 L 24–60 的暗团，与 L 89 背景差 ≥ 2 档，缩略图可辨。
- **夜景深背景**：背景 L 18–32，主体亮面抬到 L 70–85，同样差 ≥ 2 档。此时描边仍保留，但改用「外浅内深」的反向描边以免主体被背景吃掉——**这是唯一允许偏离统一描边策略的场景，仅限 S5 / S7 夜景资产，须在资产名标 `_night`。**

**验证方法**：成品转灰度，主体与背景仍清晰可分即合格；`art_asset_tools.py sheet` 出接触表做 10% 缩略图测试。

## 4. 各资产类别的表现约定

| 类别 | 约定 | 对应玩法 / 剧情 |
|---|---|---|
| **4.1 角色 `char`** | 2.5–3 头身、朝右单方向 + 代码镜像；每人 1 张常态 + 3 张状态（努力 / 失败 / 开心）；识别色只作用于衣料主块，脸、手、描边全队统一 | 七人同框 6-2；入队即解锁要求角色卡当场可点 |
| **4.2 怪物 `mon`** | **本作不设怪物**（经营养成无战斗敌人）。顾苦的鸽子归 `env` 装饰 / `fx` 特效，不建怪物族 | 避免为不存在的系统排产 |
| **4.3 场景 `env`** | 45° 俯视；S1–S4 常驻四场景优先；**漏雨屋顶不可修、水痕必须画进 S1/S2 底图**；S6 代记账小摊要有墨镜 + 遮阳帽的拙劣伪装视觉；S8 与 S2 必须共用同一张桌子的延长，不做成对立的两家店 | LOCATIONS.md 红线；S8 是「同一张桌子的延长」 |
| **4.4 UI `ui`** | 三态齐全（常态/按下/禁用，缺态写明由代码调色）；九宫格边距四个数值写进规格；**状态必须颜色 + 形状双区分**；S4 菜谱界面三态：正常 / 扣书期置灰 / 显形；置灰不是只降透明度，要叠「封条」图形 | 第三章「队伍变短」是玩法事件；V2 无配方模式 |
| **4.5 图标 `icon`** | 统一 96×96 画布、主体占 80%、统一 4px 线宽与单一圆角；单色优先，颜色由代码染；缩到 24px 仍可辨；先出 3 个基准图标定调 | P4 接单、火候判定、原料选择 |
| **4.6 特效 `fx`** | 糖霜显形用「白点由下往上浮」不用全屏光晕；面团糊脸是可爱的圆团遮挡，不做脏污；百页齐鸣是 100 页同时翻动 + 糖霜点，不做粒子爆炸 | 失败永远有笑声兜底（Design Pillar P2） |
| **4.7 动画 / 插画 `anim` / `img`** | 序列帧先出 3 个关键姿势再由人工补中间帧；终章七人同框单出一张 `img_ending_group_v1`，不做拼贴 | 终章 6-2 全员在场，不得留白 |
| **4.8 3D `mdl` / `tex`** | **本作不排产 3D**。全 2D，无 LOD、无 PBR 通道、无碰撞代理 | 与 A1 轻度休闲定位一致；若后续改 3D，须重开规格与预算文档 |

## 5. 禁忌清单（8 条 · 每条附失败表现）

| # | 禁止 | 具体失败表现（用来验收时判不合格） |
|---|---|---|
| 1 | 纯黑描边 / 纯黑阴影 | 谐星出糗桥段变惊悚；灰度图里主体出现死黑块 |
| 2 | 锐角、尖刺、尖牙、锐利道具 | 与「零锐角」锚点冲突，顾苦/雷千层看起来像真反派 |
| 3 | 镜面高光、渐变光晕、全屏泛光 | 糖霜显形变成廉价发光滤镜，L97 的独占性被破坏 |
| 4 | 写实烘焙摄影质感 / 写实解剖 | 与 2D 手绘卡通同屏即拼凑感 |
| 5 | 大面积冷灰 / 冷蓝（除夜景 S5/S7 与角色识别色） | 暖色小店基调丢掉，大团圆的温度没了 |
| 6 | 同屏 > 3 种高饱和色 | 视觉噪音，玩家分不清哪个是倒计时 |
| 7 | 状态只靠颜色区分 | 色觉障碍玩家读不出禁用 / 危险 / 增益 |
| 8 | 任何文字、水印、签名、真实品牌、受保护 IP 形象、在世艺术家个人风格 | 抠图后文字卡在资产里；合规红线 |

## 7. 一致性三道检查与冻结机制

| 检查 | 做法 | 不合格处理 |
|---|---|---|
| **同族比对** | 七位角色全部排在一张接触表上 | 统一头身比、描边色、腮红位置与辅色，只保留识别色差异 |
| **同对象状态比对** | 主角常态 / 努力 / 失败 / 开心 四态并排 | 统一左上主光方向与描边策略，不许一态换光向 |
| **跨类别比对** | 角色 + S1 场景 + 菜谱 UI + 糖霜特效拼一张同屏图 | UI 与特效不得比角色更抢眼；糖霜白面积 ≤ 15% |

**迭代收敛**：版本号 `_v1 → _v2`，旧版改名 `_deprecated` 保留不删；只改指定部分，不顺手改配色或线宽；连续两轮无实质修改意见即冻结为 v1.0 定稿。确需改锚点时，先写明「这会推翻哪几批已产出资产」。

## 8. 与玩法 / 剧情的咬合（防止美术自说自话）

| 玩法 / 剧情约束 | 美术落点 |
|---|---|
| 糖霜显形 = G3 关门落点，全作最强反馈 | `#FFF7EA` 独占最高明度，日常 UI 禁用 |
| 第三章扣书期 S4 置灰 | 置灰态要有「封条」图形，不能只降透明度 |
| 入队即解锁（5-2→S8 / 5-3→S9 / 5-4→S2） | 三个新按钮必须在同一次 session 内可见可点，用主色 + 新增角标，不做过场动画才出现 |
