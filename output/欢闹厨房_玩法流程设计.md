## 一、设计前提

### 1.1 本版推翻了什么（对照表）

| 维度 | v1.0（作废） | v2.0（本版） | 为什么必须改 |
|---|---|---|---|
| 骨架 | 每道菜走「练 / 悟 / 战」三段式关卡 | **每个 session 以开店经营为主体**，关卡退为规则态与支线 | 用户明确要求经营是主体 |
| 练习关 | 用来「学会一页」，攒手感值 | **只用来提升该点心的熟练度**；学会一页＝首次成功做出 | 用户明确指定练习的唯一功能 |
| 手感值 | 模糊的软通货，溢出转收藏册 | 删除，改为**每道菜独立熟练度 M ∈ [0,100]** | 手感值不驱动任何可验证输出 |
| 出餐品质 | 火候判定给分 | **熟练度决定完美概率**，完美＝更高收益 + 好评 | 用户明确指定概率链 |
| 顾客 | 有耐心值但未接入收益公式 | **耐心驱动收益系数与评价，归零即离场** | 用户明确指定 |
| 点击操作 | 「接单 → 选料 → 火候 → 出餐」抽象描述 | **点击食材 → 提交给顾客** 的显式两步操作链 | 用户明确指定 |
| 金币用途 | 装扮、器具（一次性 sink 为主） | **雇佣员工 + 升级设备，两者只做减负**；工资与维护构成持续 sink | 用户明确指定减负定位 |
| 长线目标 | 队伍长度＝进度条 | **自动化率＝进度条**，越到后期自动化越高 | 用户明确指定 |
| 章节规则态 | V1–V4 挂在关卡上 | V1–V4 改为**临时修改经营规则** | 骨架换了，规则态必须跟着换 |

**保留不变**：9 个场景、8 种常规玩法数量、4 种规则态数量、七幕主线、101 页、五阶排名、5-2/5-3/5-4 三次入队、大团圆铁律、剧情三插入口 G1/G2/G3。这些是设定锚定，不随玩法重构改动。

### 1.2 剧情铁律的玩法层重解释（不改 STORY_BIBLE 原文）

| 铁律 | v1.0 玩法映射 | **v2.0 玩法映射** | 是否冲突 |
|---|---|---|---|
| 显形 ≠ 学会 | 显形给题目，三段式走完才学成 | **显形仍由段位解锁、只给这一页的菜谱；首次在练习或经营中成功做出＝页学成并长糖霜插图** | 不冲突，学成条件更轻 |
| 练（反复实操攒手感） | 独立练习关 | **练习关 → 熟练度 M ↑**，M 决定完美率 | 同一动作，输出被量化 |
| 悟（做给谁吃） | 独立剧情关 | **保留 P8 剧情关，改由 T1–T5 经营触发器驱动**，在 G1 / G3 播放，不占营业时段主体 | 剧情仍在，触发方式改为经营派生 |
| 战（限时客人下完整做出来） | 独立挑战关 | **经营中的高压时段**：限时客流、干扰事件、段位评定，全部发生在 P1 接单经营里 | 更贴合原文字面 |
| 不可作弊 | 不卖配方 / 页数 / 跳过磨炼 | **不卖熟练度、不卖完美率、不卖自动化跳过**；照抄配方的页面褪回空白规则不变 | 新增三条禁售 |
| 越后越挑人 | V3 回想关 | **第 100 页回想＝把玩家失败过 / 熟练度最低的菜重做一遍**，补足熟练度 | 输出改为熟练度 |

> 结论：这次改动**没有动故事**。变的只是「玩家的手在做什么」。

### 1.4 Fun Hypothesis（重写）

> **好玩的核心是：手忙脚乱地把一份点心递到快要不耐烦的客人面前，偶尔端出一炉「完美」的；赚来的钱让店里越来越不需要自己动手，而省下的时间又能回去把某一道练到炉火纯青。**

三个动词：**递出去**（操作爽点）、**抽开手**（减负爽点）、**练回去**（养成爽点）。任何系统不服务其中至少一个，删掉。

v1.0 的「烤出来 / 留下来」偏叙事，v2.0 换成可观测的玩家动作与资源流向。

### 1.5 Design Pillars（5 条，用来否决需求）

| # | 支柱 | 玩家应感受到 | 否决示例 |
|---|---|---|---|
| **P1** | **经营永远是主体** | 每次打开游戏先看到的是客人和订单，不是关卡列表 | 把练习做成必须刷满才能开店的日常 → 否决 |
| **P2** | **练了一定看得见** | 「这道我练过，出完美的次数明显多了」 | 熟练度只进后台日志、界面不显示 → 否决 |
| **P3** | **减负不增伤** | 雇人买设备是为了少点几下，不是为了多赚一笔 | 设备升级 +10% 完美率 / 员工直接加单价 → 否决（详见 4.1） |
| **P4** | **失败永远有笑声兜底** | 客人走了、点心焦了，也想再开一局 | 耐心归零扣金币 / 掉熟练度 → 否决 |
| **P5** | **自动化不能吃掉决策** | 后期手变轻了，但「先做哪单、练哪道」还在 | 一键托管整局、玩家零输入也能通关 → 否决（A6） |

## 二、核心循环：经营是骨架

### 2.1 三层核心循环（全表重写）

| 层级 | 时间尺度 | 循环 | 反馈通道 | 失败兜底 |
|---|---|---|---|---|
| **Moment-to-moment** | 0–30 秒 | 顾客进门（订单卡）→ 点击食材完成组装 → 提交给该顾客 → 品质判定（熟练度骰）→ 耐心系数结算 → 金币 + 评价 | 食材按下高亮、品质特效（完美＝糖霜爆闪）、耐心条颜色、金币跳字、客人表情 | 客人等走 → 本单无收益，记「流失」，不扣金币、不掉熟练度（P4） |
| **Session loop** | 5–10 分钟 `[PLACEHOLDER]` | 开门 G1 → 备料 → 营业（N 波顾客）→ 中段一次干扰 / 评定 / 高压时段 → 打烊结算（扣原料、工资、维护）→ 用余额雇人 / 升设备 / 买练习原料 → 练习 1–2 道（G3 显形仪式）→ 关门 | 账本、金币余额变动、自动化率仪表、熟练度条、新页糖霜插图 | 本局收入低不扣已有进度，只影响可投资额；练习不消耗营业时长外的现实时间 |
| **Long-term** | 8–12 小时 `[PLACEHOLDER]` | 段位升 → 新页显形 → 首次做出学成 → 练到高熟练度 → 完美率↑ → 单笔收益↑ → 雇人 / 升设备 → 自动化率↑ → 单位时间接待更多顾客 → 段位升 | 五阶勺牌、101 页、熟练度总览、员工列表、设备等级、七人同框 | 低谷只有第三章一幕，且章内 3-6 回暖（设定锚定） |

### 2.2 Moment-to-moment 规格：点击食材 → 提交

| 项 | 定义 |
|---|---|
| **Purpose** | 让玩家在有限耐心下做两件事：**按对顺序点食材**、**决定先服务哪位顾客** |
| **Inputs** | 顾客订单卡（所需点心 + 耐心条）、食材台（每道菜 3–6 个食材按钮 `[PLACEHOLDER]`）、已解锁菜谱、当前熟练度 M、当前自动化率 |
| **玩家动作** | ① 选目标顾客 → ② 按配方顺序点击食材（可跨顾客交错）→ ③ 点「提交」把成品递给该顾客 |
| **投料顺序（全局固定）** | 所有点心共用一条工序：乳脂与液体基底 → 蛋与油脂 → 粉类成型 → 熬糖调味 → 点缀装饰。食材台按钮按同一顺序排布，V1 干扰插入后仍按此序；配方不随机排列 |
| **Outputs** | 一次品质判定结果、单笔金币、评价档、该顾客耐心剩余、连击 / 保底计数更新 |
| **Failure state** | 点错食材 → 该步可撤销回退（不消耗耐心以外的资源）；耐心归零 → 顾客离场，本单收益 0。**倒计时内按序提交必出货，随机判定不产生失败品质** |
| **边界** | 提交后不可撤回；同一顾客只接一次提交；员工 / 设备接管的步骤在界面上仍显示为「自动完成」的高亮，不隐藏操作链（P5 可见性） |

> **反馈通道优先**：玩家说「感觉不对」时，先查耐心条是否看得见、完美特效是否够响、食材按下是否有即时高亮，再怀疑概率模型。这是通道问题，不是数值问题。

### 2.3 一局（session）流程

```
G1 开门钩子（≤20s，可跳过）
   ↓
备料：用上一局余额买原料（金币 → 原料，持续 sink）
   ↓
【营业时段 · 主体】  N 波顾客 [PLACEHOLDER 2–3 波]
   每波：顾客进门 → 点食材 → 提交 → 品质判定 → 耐心结算 → 金币/评价
   中段插入：V1 干扰 / P7 评定 / 高压时段（三者择一，不叠加）
   ↓
打烊结算 P6：收入 − 原料 − 员工工资 − 设备维护 = 可支配余额
   ↓
投资决策（本局最重要的长期决策）
   ├─ 雇员工 / 升设备  → 自动化率 ↑（下一局少点几下）
   ├─ 买练习原料        → 熟练度 ↑（下一局完美率 ↑）
   └─ 存着              → 无收益，纯缓冲
   ↓
练习时段 P2：1–2 道菜，M ↑；首次做出 → 新页长糖霜插图（G3）
   ↓
G3 关门落点（≤40s）：显形仪式 / 章末钩子 / 入队动画
```

### 2.4 长期闭环：金币与时间的双向投资

```
        经营（营业时段）              投资（打烊后）
        ┌────────────┐              ┌────────────┐
        │ 点食材→提交 │ ──金币──→   │ 雇人/升设备 │ ──自动化率↑──→ 单位时间接待更多顾客
        │ 耐心→收益   │              │ 买练习原料  │ ──熟练度↑──→ 完美率↑──→ 单笔收益↑
        └────────────┘ ←────────────└────────────┘
              ↑                           │
              └──── 省下的操作时间 ←──────┘
```

**这里有一个必须摊开讲的设计张力**：练习不直接产金币，却要占打烊后的时间与原料。玩家会本能地把钱全投自动化，然后发现完美率原地踏步、单笔收益不涨。反过来只练不雇人，则手忙脚乱接不完客人，完美率再高也没用。

两条投资不是「哪个更优」，是**必须交替推进**。文档不假装它们一致，第七节用 sources/sinks 把这条张力量化，第八节把「玩家只投一边」列为 playtest 失败信号。

## 三、四条核心机制与数值模型

### 3.1 模型 A：熟练度 → 完美率 → 收益

**熟练度 M**：每道点心独立，`M ∈ [0,100]`。来源只有三个：练习关（主要）、经营中实际出餐（少量）、回想关补足（第五章）。**金币不可购买 M**（P3 / 不可作弊铁律）。

**每次提交做一次品质判定**，三档 `[PLACEHOLDER 全部]`：

| 品质 | 概率函数 | 收益系数 Q | 评价 | 视觉反馈 |
|---|---|---|---|---|
| **完美** | `p_perfect = clamp(0.05 + 0.0055 × M, 0.05, 0.60)` | ×1.5 | 好评（覆盖耐心） | 糖霜爆闪、糖老书「勉强能算个东西」 |
| **普通** | `1 − p_perfect` | ×1.0 | 按耐心档 | 常规出餐 |

**Rationale**：
- 低熟练度仍留 5% 完美，让新手第一局就能撞见一次「这游戏的高光长什么样」，这是留存钩子，不是随机放水。
- 高熟练度封顶 60%，保留波动张力；若允许 100% 完美，后期经营会退化成无判定的点击流水线。
- 倒计时内提交不设失败档：普通品质保底 Q=1.0。熟练度只决定上行波动（有多好），不制造下行惩罚；唯一负反馈是耐心归零离场（P4）。
- 系数与斜率全部标 `[PLACEHOLDER]`：验证路径是 1000 次出餐的 Monte Carlo 模拟 + 20 人 playtest 的「练了有没有用」主观量表，两者结果不一致时优先改可见性（熟练度条 / 完美计数），再改斜率。

**保底机制** `[PLACEHOLDER]`：连续 N 单未出完美后，第 N+1 单强制完美，防止连续非完美被感知为「练了白练」。N 待 playtest 定，当前不填数。

### 3.2 模型 B：顾客耐心 → 收益系数 / 评价 / 离场

| 项 | 定义 |
|---|---|
| 初始耐心 | `P0` 秒 `[PLACEHOLDER]`，随段位、顾客类型、菜品点击步数变化 |
| 衰减 | 进门起线性下降，提交瞬间锁存剩余比例 `p = P_remain / P0 ∈ [0,1]` |
| 收益系数 | `T(p) = 0.5 + 0.5 × p` `[PLACEHOLDER]`（满耐心 ×1.0，半耐心 ×0.75） |
| 评价（普通品质时） | `p ≥ 0.6` 好评 / `0.3 ≤ p < 0.6` 中评 / `p < 0.3` 差评 `[PLACEHOLDER 阈值]` |
| 耐心归零 | 顾客离场，本单收益 0，记「流失客数」，**不额外给差评、不扣金币、不掉熟练度**（P4） |

**单笔收益公式**：

```
收益 = 基础价 B × 品质系数 Q × 耐心系数 T(p)
```

**Rationale**：耐心同时接收益与评价，但两者斜率不同——评价用阶梯（明确、可读），收益用线性（平滑、不制造「差一秒亏一半」的挫败）。基础价 B 随菜式与段位变化 `[PLACEHOLDER]`。

### 3.3 完美 × 耐心的结算优先级（默认解释，待商讨 Q1）

用户原话中「吃到完美的食物就会好评，不会影响收益评价」有三种可读解释。本版采用**默认 A**，另两种列为商讨候选：

| 方案 | 完美时的评价 | 完美时的收益 | 采用 |
|---|---|---|---|
| **A 默认** | 强制好评（覆盖耐心档） | `B × 1.5 × T(p)`，**耐心系数照常生效** | ✔ |
| B | 强制好评 | `B × 1.5`，完全免疫耐心扣减 | 待商讨 |
| C | 只给好评、不加成收益 | `B × T(p)`，完美纯属评价事件 | 待商讨 |

选 A 的理由：它同时满足「熟练度影响收益」（模型 A 成立）与「耐心影响收益」（模型 B 不被绕过）；若选 B，练满后耐心系统对高熟练度玩家整体失效，模型 B 的长期价值塌掉。

**结算顺序（唯一，不允许并列判定）**：
1. 判定品质（完美 / 普通）→ 2. 锁存提交瞬间的 `p` → 3. 算 `Q × T(p)` → 4. 判定评价档（完美覆盖好评、普通按 p 阶梯）→ 5. 发放金币与好评率。

### 3.4 评价的回收口：不让它变成一串没用的字

| 评价汇总 | 影响 | Rationale |
|---|---|---|
| 当日好评率 | 次日进店顾客基数 `[PLACEHOLDER]` | 让「服务快」和「做得好」都指向同一个经营目标 |
| 流失客数 | 当日评价上限封顶 `[PLACEHOLDER]` | 防止靠拖时间刷好评 |
| 累计好评率 | 糖勺榜评定的「谁在吃」项（4-7 条例松口、第五章改条例） | **直接接上剧情**：评审会从不认心意到加一行「谁在吃」 |
| 差评 | 只影响好评率，不扣金币 | P4：失败不惩罚 |

> 这是本次重构里第二处「用操作系统讲剧情」：4-7 周伯亮明身份、评审会松口，在系统里就是「好评率第一次进入评定公式」。

### 3.5 随机性与玩家能动性

| 风险 | 处理 |
|---|---|
| 玩家觉得「练了没用，全看脸」 | 熟练度条常驻 S4 与出餐界面；每道菜显示「近 20 单完美次数」，用可观测频率替代概率说明 |
| 连续非完美造成挫败 | 保底机制（3.1） |
| 玩家把完美率当成唯一目标 | 自动化投资同样重要：完美率提高单笔，自动化提高单量，两条曲线都不封死 |
| 随机被商业化利用 | 不卖幸运道具、不卖「必出完美」、不卖熟练度（禁售清单） |

## 四、减负与自动化曲线

### 4.1 定位：减负 ≠ 增伤（P3，最容易写歪的一条）

| 员工 / 设备**会**影响 | 员工 / 设备**不会**影响 |
|---|---|
| 需要玩家手动点击的步数 | 熟练度 M |
| 单位时间可服务的顾客数（吞吐） | 完美率 / 品质判定 |
| 并行顾客上限 | 单笔基础价 B |
| 出餐等待时间 | 顾客耐心初值 P0 |
| 结算 / 备料 / 上菜的自动接管 | 剧情段位评定结果 |

**吞吐提高 → 单位时间金币提高**，这是间接的、玩家能理解的因果；不是给每单偷偷加 10%。若把完美率也挂到设备上，玩家会算出「买设备 = 买收益」，练习系统当场作废，Fun Hypothesis 的第三个动词「练回去」消失。

### 4.2 员工系统（P4）

| 项 | 定义 |
|---|---|
| 雇佣 | 打烊后用金币一次性雇佣；岗位槽随段位开放 `[PLACEHOLDER]` |
| 岗位 | 备料（自动点前 N 个食材）/ 烤制（自动完成火候步）/ 上菜（自动提交给耐心最低的顾客）/ 收银（自动结算并列账） |
| 自动接管规则 | 员工只接管**已学会**菜品的固定步骤；新菜首做、异常订单、干扰事件强制手动（A6） |
| 持续成本 | 每 session 工资（**持续 sink**），从打烊收入扣 |
| Failure state | 余额不足发工资 → 员工不消失，改为「今天请假」，该岗位本局无自动接管（喜剧气泡，不裁员、不扣进度） |

> 「请假」而不是「解雇」是刻意的：调性红线不允许失败带真实损失，且大团圆设定里没人离场。

### 4.3 设备系统（P5）

| 项 | 定义 |
|---|---|
| 升级 | 打烊后用金币升级，等级 `[PLACEHOLDER]` 1–5 |
| 效果 | 每级减少 1 个手动点击步骤 / 缩短出餐等待；**不减少食材种类、不改配方** |
| 持续成本 | 每 session 维护费（**持续 sink**）；漏雨屋顶仍不可修（设定红线） |
| 与 V2 的冲突 | 第四章无配方模式期间，设备**不显示食材名称提示**，只自动完成已点选的步骤，避免绕过「凭手感」 |
| Failure state | 维护费不足 → 设备本局降级运行（少接管一步），不损坏、不丢失等级 |

### 4.4 自动化率曲线与「决策不能消失」红线

**自动化率 A = 被自动接管的点击步数 / 总点击步数**，`A ≤ 70%` `[PLACEHOLDER]`（A6）。

```
序章   0%  ████████████████████  全手动：点食材、提交、结算全靠玩家
一章  20%  ████████████████░░░░  首位员工（自动备料）
二章  40%  ████████████░░░░░░░░  烤炉升级（自动火候）
三章   0%  ████████████████████  ← 3-3 剥离：员工离岗、设备停机（全作唯一一次倒退）
四章  30%  ██████████████░░░░░░  无配方期逐步恢复，手动强度仍是全作最高
五章  70%  ██████░░░░░░░░░░░░░  5-2 / 5-3 / 5-4 三次入队，三条自动化线接通
终章   0%  ████████████████████  自由炉：主角主动关掉全部自动化
```

**P5 红线**：即使 A = 70%，玩家每局仍必须做三类决策 —— ① 先服务哪位顾客（排序）；② 打烊后把钱投自动化还是投熟练度（2.4 的张力）；③ 新菜首做与干扰事件的手动应对。若 playtest 出现「挂着不动也能过关」，先砍自动接管范围，别加新玩法。

### 4.5 三次入队 = 三条自动化线（R3 重定义）

| 节点 | 角色 | 入队即解锁 | 自动化线 | 旧身份的新用法（设定锚定） |
|---|---|---|---|---|
| **5-2** | 雷千层 | S8 技法台 | **练习自动化**：练习时段可委托，按他的标准自动累计熟练度 | 继续挑刺，改成替全店校准火候 |
| **5-3** | 顾苦 | S9 咕咕外送站 | **提交 / 外送自动化**：鸽子接管一部分上菜与外送单 | 继续捣乱，改成防捣乱演练教材 |
| **5-4** | 沈如意 | S2 柜台 | **结算自动化**：账本自动平账、工资与维护费自动列支 | 继续算账，改成替全店算 |

> v1.0 的「入队即解锁」偏加成，v2.0 改成「入队即减负」——更贴合用户给的经营主体，也更贴合大团圆：每个人来，都是来帮主角少点几下的。

### 4.6 第三章：用操作系统讲背叛（本版最强的一处咬合）

3-3 摘星封炉扣书，v1.0 写的是「剥离全部加成」。v2.0 把它具体化：

| 被剥离项 | 玩家立刻感受到 |
|---|---|
| 员工离岗（沈如意出走 + 其余岗位清空） | 食材按钮重新全部要手点 |
| 设备停机 | 出餐等待恢复初始值 |
| S4 菜谱界面置灰 | 熟练度条不可见、显形题目也不给 |
| 工资与维护费停收 | 账本上少两行支出，反而更像「人真的走了」 |

玩家在 3-1 已经习惯 40% 自动化，3-3 一局之内被打回 0%，手上点击量直接翻倍。**不需要一句解释台词**。3-6 顾苦那袋糖对应「一位员工以临时帮工身份回来」，是自动化率第一次回升，情绪回暖也落在手指上。

每种都写清 purpose / inputs / outputs / failure state；写不出来的系统不进 GDD。

### 5.4 四种规则态（临时改经营规则，不是新玩法）

| ID | 规则态 | 生效窗口 | 改了什么 | 剧情对应 |
|---|---|---|---|---|
| **V1** | **干扰事件池** | 一章起，按段位逐级投放 | 糖罐换盐 / 温度计调乱 / 胡椒烟雾弹 / 鸽子占座 / 伪装评论家打一星 / 改门牌；**每次都真实增加点击步数或缩短耐心**，但必带自食其果的喜剧落点 | 1-4 换盐反做出「海盐焦糖」、2-4 烟雾弹、5-1 全场换苦精；5-3 后转演练教材 |

### 7.1 Sources & Sinks（全表重写）

| Sources（进） | 说明 | Sinks（出） | 说明 | 性质 |
|---|---|---|---|---|
| **出餐收入** | P1 每单 `B × Q × T(p)`；**主来源** | **原料采购** | 每 session 备料，随菜单宽度与练习量增长 | 持续 |

| — | — | 干扰事件重做成本 | V1 增加的原料消耗 | 偶发 |
| — | — | **鸽子饲料 / 外送队维护** | 5-3 后并入员工工资口径，不重复计 | 持续 |

**v1.0 的最大风险「装扮是一次性 sink、第五章金币溢出」在 v2.0 被结构性解决**：员工工资与设备维护费随自动化率上升而上升，是**跟着主体玩法一起增长的持续 sink**。自动化越高，收入越高，维护也越高——收支两端同向增长，通胀不再靠外挂一个「鸽子饲料」来堵。

**判定依据**：v1.0 的一次性 sink 购买次数有限而金币按 session 持续产出，缺口在买完后单调扩大；v2.0 把 sink 挂在「在岗人数 × 设备等级」上，这两个量随进度单调增长。触发条件与影响组件明确，根因是 sink 是否与主循环同源。**验证路径**：按 25 session 做一次收支 Monte Carlo，观察第五章金币余额斜率是否趋平 `[PLACEHOLDER]`。

**禁售清单（不可作弊铁律 + P3）**：不卖配方、不卖页数、不卖熟练度、不卖完美率 / 必出完美道具、不卖「跳过练习」、不卖自动化跳过。商业化若与之冲突，改商业化，不改铁律。

### 8.2 Paper Prototype（先纸面，再代码）

**5 张卡 / 10 分钟**（v1.0 是 3 张，新增熟练度与耐心两张）：
① 一页空白菜谱（菜名 + 熟练度格）② 一张顾客订单卡（带可擦写的耐心条）③ 一张食材卡（3–6 个格子，按顺序点）④ 一张干扰事件（糖罐换盐 → 多点一格）⑤ 一张打烊账本（收入 / 工资 / 维护 / 投资双项抉择）。

**只验证两件事**：
1. 玩家在没有美术与音效时，会不会因为「快等走的客人面前端出一份完美」而笑出来、主动要求再来一局。
2. 打烊后玩家会不会**在「雇人」和「练一道」之间真的犹豫**。不犹豫 → 2.4 的张力没成立，先调两条投资的回报斜率，别写经营代码。

### 8.3 Playtest 失败信号（先定义坏掉长什么样）

| 级别 | 信号 | 优先排查 | 不能先做的事 |
|---|---|---|---|
| **A 核心循环坏** | 序章重试 5 次仍不懂「点食材 → 提交」 | 反馈通道：食材按下高亮、订单与顾客的对应关系、耐心条可见性 | 别改概率模型、别加教程文字 |
| **B 养成无效感** | 玩家说「练了没用 / 全看脸」 | 熟练度条与近 20 单完美次数是否常显；再查斜率与保底 | 别直接调高完美率上限 |
| **C 决策消失** | 后期挂机也能过关，或玩家说「没我什么事了」 | A6 上限、新菜首做与异常事件是否强制手动 | 别加新玩法硬凑操作量 |
| **D 经济坏** | 第五章金币溢出，或工资维护压到雇不起 | 员工工资 / 设备维护是否随收入同向增长 | 别加装扮硬凑消费、别删持续 sink |
| **E 耐心挫败** | 离场率过高、玩家频繁重开 | P0 与点击步数是否联调、并行顾客数是否超 A1 | 别把差评改成扣金币 |
| **F 练习被跳过** | 玩家几乎不进 P2，把钱全投自动化 | 练习产物售价、熟练度增量、完美收益系数 | 别把练习设成开店前置条件（违反 P1） |
| **G 叙事咬合坏** | 5-2/5-3/5-4 入队后没点新按钮；终章有人缺席 | R3 当场可操作、6-2 七人同框、S6 已撤摊 | 别加更长过场、别留「会不会回来」 |
