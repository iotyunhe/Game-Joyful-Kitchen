01 / Assumptions & Pillars

设计前提

本版推翻骨架、保留设定；未给定的四项仍先摆假设，写清「测出来不是这样要重画哪一块」

FUN HYPOTHESIS · 一句话
好玩的核心是：手忙脚乱地把一份点心递到快要不耐烦的客人面前，偶尔端出一炉「完美」的；赚来的钱让店里越来越不需要自己动手，而省下的时间又能回去把某一道练到炉火纯青。

三个动词：递出去（操作爽点）、抽开手（减负爽点）、练回去（养成爽点）。任何系统不服务其中一个，删掉。

1.1 本版推翻了什么

维度v1.0（作废）v2.0（本版）
骨架每道菜走「练 / 悟 / 战」三段式关卡每个 session 以开店经营为主体；关卡退为规则态与支线
练习关用来「学会一页」，攒手感值只提升该点心的熟练度 M；学成＝首次成功做出
手感值模糊软通货，溢出转收藏册删除，改为每道菜独立 M ∈ [0,100]
出餐品质火候判定给分熟练度决定完美概率，完美＝更高收益 + 好评
顾客有耐心值但未接进收益公式耐心驱动收益系数与评价，归零即离场
点击操作「选料 → 火候 → 出餐」抽象描述点击食材 → 提交给顾客 的显式两步链
金币用途装扮、器具（一次性 sink 为主）雇员工 + 升设备，只做减负；工资与维护为持续 sink
长线目标队伍长度＝进度条自动化率＝进度条，越到后期自动化越高

1.2 剧情铁律的玩法层重解释（STORY_BIBLE 原文未改）

铁律v2.0 玩法映射结论
显形 ≠ 学会显形仍由段位解锁、仍只给题目；首次成功做出＝页学成 + 糖霜插图不冲突
练（反复实操）练习关 → 熟练度 M ↑，M 决定完美率输出被量化
悟（做给谁吃）保留剧情关，改由 T1–T5 经营触发器驱动，在 G1 / G3 播放，不占营业时段主体剧情仍在
战（限时客人下做出来）经营中的高压时段：限时客流、干扰、评定，全部发生在接单经营里更贴合原文
不可作弊新增禁售：熟练度、完美率、自动化跳过扩充不改写
越后越挑人第 100 页回想＝重做失败过 / 熟练度最低的菜，补足 M输出改为 M

1.3 Design Pillars（5 条，用来否决需求）

P1 经营永远是主体

打开游戏先看到客人和订单，不是关卡列表。练习不得设成开店前置。

P2 练了一定看得见

熟练度条与近 20 单完美次数常驻，用可观测频率替代概率说明。

P3 减负不增伤

雇人买设备只为少点几下。设备 +10% 完美率、员工加单价 → 否决。

P4 失败有笑声兜底

客人走了、点心焦了，不扣金币、不掉熟练度，必带喜剧落点。

P5 自动化不吃掉决策

上限 70% [PLACEHOLDER]；排序、投资、新菜首做强制手动。

A3 单局时长

[PLACEHOLDER] 8 分钟；一变，营业时段与 25 session 切分全部重画。

核心循环：经营是骨架

2.1 点击食材 → 提交（显式规格）

项定义
Purpose有限耐心下做两件事：按对顺序点食材、决定先服务哪位顾客
Inputs顾客订单卡（点心 + 耐心条）、食材台（每道 3–6 个按钮 [PLACEHOLDER]）、熟练度 M、自动化率 A

Outputs品质结果、单笔金币、评价档、耐心剩余、保底计数更新
Failure点错可撤销；耐心归零 → 离场、收益 0；失手 → 低价卖出 + 喜剧气泡
反馈通道优先　玩家说「感觉不对」时，先查耐心条是否看得见、完美特效是否够响、食材按下是否即时高亮，再怀疑概率模型。这是通道问题，不是数值问题。

四条核心机制与数值模型

熟练度 → 完美率 → 收益；耐心 → 收益与评价；两条链在提交瞬间合并结算

3.1 模型 A：熟练度 → 完美率 → 收益

品质概率函数 [PLACEHOLDER]收益 Q评价视觉反馈
完美clamp(0.05 + 0.0055×M, 0.05, 0.60)×1.5好评（覆盖）糖霜爆闪 + 糖老书「勉强能算个东西」
普通1 − p_perfect − p_fail×1.0按耐心档常规出餐
失手clamp(0.20 − 0.0018×M, 0.02, 0.20)×0.5差评（覆盖）面团糊脸 + 材料成本价返还
低端留 5% 完美

新手第一局就能撞见高光长什么样，是留存钩子，不是随机放水。

高端封顶 60%

若允许 100% 完美，后期经营会退化成无判定的点击流水线。

失手不归零

下限 2%，喜剧落点始终存在，符合调性红线。

保底机制

连续 N 单未出完美后第 N+1 单强制完美；N [PLACEHOLDER]，防「练了白练」。

3.2 模型 B：耐心 → 收益 / 评价 / 离场

项定义
初始耐心 P0[PLACEHOLDER] 秒，随段位、顾客类型、点击步数变化；进门起线性下降
收益系数T(p) = 0.5 + 0.5p（满耐心 ×1.0，半耐心 ×0.75）[PLACEHOLDER]
评价（普通品质）p ≥ 0.6 好评 / 0.3 ≤ p < 0.6 中评 / p < 0.3 差评 [PLACEHOLDER]
耐心归零顾客离场，本单收益 0，记「流失客数」；不额外差评、不扣金币、不掉 M（P4）

Rationale：评价用阶梯（明确可读）、收益用线性（平滑，不制造「差一秒亏一半」的挫败）。

3.3 完美 × 耐心的结算优先级（默认方案 A，待商讨 Q1）

方案完美时评价完美时收益采用
A 默认强制好评（覆盖耐心档）B × 1.5 × T(p)，耐心系数照常✔
B强制好评B × 1.5，完全免疫耐心扣减待商讨
C只给好评B × T(p)，完美纯属评价事件待商讨
为什么默认选 A　它同时保住「熟练度影响收益」与「耐心影响收益」；选 B 会让练满之后的耐心系统对高熟练度玩家整体失效。结算顺序唯一：判品质 → 锁存 p → 算 Q×T(p) → 判评价档（完美/失手覆盖）→ 发金币与好评率。

04 / Automation Curve

减负与自动化曲线

员工与设备只减少手动点击，不碰品质；自动化率取代队伍长度，成为新的进度条

4.1 定位：减负 ≠ 增伤（P3）

会影响不会影响
需要玩家手动点击的步数 / 单位时间可服务顾客数 / 并行顾客上限 / 出餐等待 / 结算与备料的接管熟练度 M、完美率、品质判定、单笔基础价 B、耐心初值 P0、段位评定结果
最容易写歪的一条　吞吐提高 → 单位时间金币提高，这是玩家能理解的间接因果；不是给每单偷偷加 10%。把完美率挂到设备上，玩家会算出「买设备＝买收益」，练习系统当场作废，Fun Hypothesis 的「练回去」消失。

4.2 员工与设备

员工 P4

岗位：备料 / 烤制 / 上菜 / 收银，各自动接管一段固定步骤。只接管已学会菜品；新菜首做、异常订单、干扰事件强制手动。

成本：一次性雇佣 + 每 session 工资（持续 sink）。余额不足 → 该岗位「今天请假」，不裁员、不扣进度。

设备 P5

升级 1–5 级 [PLACEHOLDER]，每级减少 1 个手动步骤或缩短出餐等待；不改食材种类、不改配方。

成本：一次性升级 + 每 session 维护费（持续 sink）。维护不足 → 本局降级运行，不掉等级。漏雨屋顶仍不可修。

4.3 自动化率曲线（A ≤ 70% [PLACEHOLDER]）

图 4 · 自动化率每章都变，玩家每局都能感到手变轻或变重
P5 红线　即使 A = 70%，玩家仍必须做三类决策：先服务谁、打烊后投自动化还是投熟练度、新菜首做与干扰应对。playtest 出现「挂着不动也能过关」，先砍自动接管范围，别加新玩法。

4.4 三次入队 = 三条自动化线（R3 重定义）

节点角色入队即解锁自动化线旧身份的新用法
5-2雷千层S8 技法台练习自动化：委托练习累计 M继续挑刺，改成替全店校准火候
5-3顾苦S9 咕咕外送站提交 / 外送自动化：鸽子接管上菜与外送单继续捣乱，改成防捣乱演练教材
5-4沈如意S2 柜台结算自动化：自动平账、列支工资维护继续算账，改成替全店算

v1.0 的「入队即解锁」偏加成，v2.0 改成「入队即减负」——每个人来，都是来帮主角少点几下的。

4.5 第三章：用操作系统讲背叛

被剥离项玩家立刻感受到
员工离岗（沈如意出走 + 岗位清空）食材按钮重新全部要手点
设备停机出餐等待恢复初始值
S4 菜谱界面置灰熟练度条不可见、显形题目也不给
工资与维护费停收账本少两行支出，反而更像「人真的走了」
不需要一句解释台词　玩家在 3-1 已习惯 40% 自动化，3-3 一局内被打回 0%，手上点击量直接翻倍。3-6 顾苦那袋糖对应「一位临时帮工回来」，自动化率首次回升，情绪回暖也落在手指上。
